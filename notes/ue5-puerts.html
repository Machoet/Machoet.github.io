UE5 Puerts 使用文档

Puerts（普洱TS）是腾讯开源的游戏引擎多语言脚本方案，在 Unreal Engine 中以 TypeScript / JavaScript 编写游戏逻辑。本文整理其安装、TypeScript 环境配置与核心用法， 内容依据官方文档编写。

1. Puerts 简介

Puerts 是覆盖 Unity / Unreal / .NET 的多语言脚本方案，其中 Unreal 端目前仅支持 JavaScript / TypeScript。核心原理是在 UE 引擎中嵌入 JS 虚拟机，并默认导入全部 UE 反射 API（UCLASS / UPROPERTY / UFUNCTION / USTRUCT / UENUM 及蓝图），TypeScript 即可直接调用；非反射的 C++ API 也可以通过“基于模板的静态绑定”手工暴露给脚本层。

支持的引擎版本为 UE 4.22 ~ 最新版（含 UE5.x）。

1.1 三种脚本后端对比

后端特点调试支持适用场景
V8（默认） 高性能，Release 包内置 支持 常规开发首选
QuickJS 包体极小，额外支持 H5 / 小游戏平台 不支持 对包体大小敏感的项目
Node.js 可使用 npm 生态，包体最大 支持 需要 npm 库的工具链场景

平台方面，V8 / Node.js 后端支持 Windows / Mac / Linux / Android / iOS；QuickJS 额外支持 H5 与小游戏平台。

2. 安装

2.1 Release 包安装（推荐）

  1. 前往 GitHub Releases 页面，下载以 Unreal_vx.x.x 开头的发布包（已内置 V8 后端）。
  2. 解压到项目的 YourProject/Plugins/ 目录即可完成安装。

2.2 源码安装

  1. 执行 git clone https://github.com/Tencent/puerts.git。
  2. 将仓库中的 puerts/unreal/Puerts 目录拷贝到 YourProject/Plugins/。
  3. 源码方式不含脚本后端，需单独下载并放入 Plugins/Puerts/ThirdParty/：
    • V8：下载对应版本（UE4.25+ 可选 8.4.371.19 / 9.4.146.24 / 10.6.194 / 11.8.172），并修改 JsEnv.build.cs 中的 UseV8Version；
    • Node.js：放入后在 JsEnv.build.cs 中设置 UseNodejs = true；
    • QuickJS：放入后在 JsEnv.build.cs 中设置 UseQuickjs = true。

2.3 注意事项

  • 纯蓝图工程不会自动编译 C++ 插件，需要先在编辑器中添加任意一个 C++ 类，把项目转为 C++ 工程后再启用插件。
  • Mac 平台下动态库会被系统隔离，需执行 sudo xattr -r -d com.apple.quarantine *.dylib 解除。

3. 一键配置 TS 环境（Setup-TSEnv.bat）

本工作流使用项目根目录的 Setup-TSEnv.bat 一键完成 TypeScript 开发环境配置。双击运行后脚本自动完成以下手动步骤：

  • 检查本机 Node.js 环境并安装所需 npm 依赖（TypeScript 编译器等）；
  • 在项目根目录生成 tsconfig.json（关键字段见下方对照表）；
  • 创建 TypeScript/ 源码目录；
  • 启动 tsc 监视编译，将产物持续输出到 Content/JavaScript/（虚拟机默认加载根目录）。
说明：Setup-TSEnv.bat 为本项目自有工具脚本，Puerts 官方文档中并无此脚本； 其封装的等效手动流程见 官方安装页。

3.1 等效手动步骤对照

手动步骤说明
创建源码目录 在项目根目录新建 TypeScript/，作为 TS 源码存放位置
编写 tsconfig.json 置于 YourProject/tsconfig.json，关键字段见下方示例
安装编译器 安装 TypeScript 编译器（版本兼容性见常见问题）
监视编译 运行 tsc -w，编译产物输出到 Content/JavaScript/

tsconfig.json 关键字段

{
  "compilerOptions": {
    "target": "esnext",
    "module": "commonjs",
    "outDir": "Content/JavaScript",
    "typeRoots": ["Typing", "./node_modules/@types"],
    "experimentalDecorators": true
  },
  "include": ["TypeScript/**/*"]
}

其中 experimentalDecorators 仅在使用装饰器（如自动绑定模式设置 UFUNCTION / UPROPERTY specifiers）时需要开启。

4. 快速上手

4.1 生成 UE 类型声明（Puerts.Gen）

  • 通过编辑器菜单或控制台命令 Puerts.Gen 生成 ue.d.ts（UE 原生类型）与 ue_bp.d.ts（蓝图类型），生成后 IDE 即有完整智能提示。
  • 蓝图声明默认增量生成；如遇 d.ts 报错，可执行 Puerts.Gen FULL 全量重生成。
  • 可指定路径仅生成部分蓝图声明：Puerts.Gen PATH=/Game/StarterContent。

4.2 手动构造虚拟机模式（FJsEnv）

  1. 在 C++ 中（如 GameInstance::OnStart）构造 puerts::FJsEnv 实例；
  2. 调用 JsEnv->Start("QuickStart", Arguments) 传入入口脚本名（不带后缀）；
  3. TS 端通过 import {argv} from 'puerts' 获取 Start 传入的参数。

C++ 侧（最小示例）

// 最小示例（C++ 侧）
JsEnv = MakeShared<puerts::FJsEnv>();
JsEnv->Start("QuickStart", Arguments);

TypeScript 侧

// TS 侧获取参数
import * as UE from 'ue'
import {argv} from 'puerts';
let world = (argv.getByName("GameInstance") as UE.GameInstance).GetWorld();

4.3 自动绑定模式（Automatic Binding Mode）

无需手动构造 FJsEnv，由 PuertsModule 自动启动虚拟机：

  1. 关闭编辑器，在 Plugins/Puerts 目录执行 node enable_puerts_module.js；
  2. 在 YourProject/TypeScript/ 新建 TS 文件，继承 UE 类并 export default；
  3. 重新生成声明文件后，该类即可在 UE 编辑器中直接使用。
命名约束：自动绑定模式下，文件名、类名与 default export 三者必须完全一致。

5. 核心用法

5.1 访问 UE 反射 API

  • import * as UE from 'ue' 即可访问全部反射类；
  • 类名规则为去掉 C++ 前缀：FVector → Vector、AActor → Actor；
  • 加载蓝图类：UE.Class.Load("path/to/your/blueprint/file")。

5.2 继承 UE 类与装饰器（自动绑定模式）

  • 支持 Constructor 定义、覆写蓝图事件（ReceiveBeginPlay / ReceiveTick）、输入轴映射与 RPC 函数；
  • 数据类型注解：@cpp:int / @cpp:text / @cpp:name / @cpp:byte / @no-blueprint；
  • 装饰器可设置 UFUNCTION / UPROPERTY specifiers（如 BlueprintCallable、Replicated 等）。
性能提示：自动绑定模式会产生密集的跨语言调用，官方建议仅将其作为 “原有系统与脚本系统的边界”使用，不要大面积替代蓝图。

5.3 蓝图 Mixin

可以把一个 TS 类 mixin 到蓝图类（或原生 UCLASS）上，无需继承即可混入逻辑。 Mixin 是 puerts::FJsEnv 的固有特性，任意虚拟机实例均支持。

5.4 委托与事件绑定

委托类型TS 用法
DYNAMIC_DELEGATEDemoActor.BasicNotify.Bind(callback)
带引用参数用 $unref 读值、$set 写回引用参数
带返回值回调函数直接 return
DYNAMIC_MULTICAST_DELEGATE.Add(callback) 添加监听
手动创建委托toDelegate(owner, func)；或 toManualReleaseDelegate(func)（需手动释放）

5.5 C++ 与 TS 的其他交互

  • JsObject：C++ 端可用 FJsObject 直接读写 JS 对象属性、调用 JS 函数；
  • std::function 绑定：C++ 端的 std::function<int(int,int)> 可直接接收 TS 闭包；
  • 非反射 API：通过“基于模板的静态绑定”声明后即可在 TS 中调用。

6. 常见问题

6.1 调试

  • 启用调试：项目设置 → Plugins → Puerts Settings → 勾选 Debug Enable，配置端口（默认 8080）；
  • 手动 VM 模式：构造 FJsEnv 时传入端口号（如 1337），可调用 WaitDebugger() 等待调试器连接；
  • VSCode 配置：在 .vscode/launch.json 中添加 type: "node"、request: "attach" 与对应端口后附加调试；
  • UE 默认开启 “Use Less CPU when in Background”，调试时建议关闭，避免后台帧率过低影响断点响应。

6.2 打包发布

必做项：JS 脚本不是 UE 资产文件，打包时必须在 项目设置 → 打包 → Additional Non-Asset Directories to Package 中添加 Content/JavaScript，否则脚本不会进包。

另外注意：打包后 FName 的大小写行为与编辑器不一致（编辑器大小写敏感、运行时不敏感），可能导致字段查找失败。

6.3 其他高频问题

问题要点
TypeScript 版本兼容 继承引擎类功能依赖 TS 编译器，已验证可用版本：3.4.5 / 4.4.4 / 4.7.4 / 4.8.2；不支持 ≥ 4.8.3
UE5 “Construct on illegal thread” 关闭 AsyncLoadingThreadEnabled（UE5 默认开启）
“access a invalid object” 切换场景时 UE 会强制删除 Actor，TS 侧应及时清理引用；无法定位时可用 try-catch 兜底
GC 注意事项 TS stub 对象默认持有 UE 对象强引用，但 UE 可强制销毁对象、不受 JS GC 管理；切换场景时建议调用 FJsEnv::RequestFullGarbageCollectionForTesting
ue_bp.d.ts 报错 蓝图路径含非法字符时，可将其加入黑名单或使用 Puerts.Gen PATH=… 指定路径生成
多线程栈溢出 “Maximum call stack size exceeded”：在 JsEnv.Build.cs 中添加 THREAD_SAFE 宏；QuickJS 后端不支持多线程
